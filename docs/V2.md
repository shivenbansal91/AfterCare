# V2 architecture and operation

## Personal review and reminders

The October 19 revision replaces mandatory clinician approval with personal prescription review. React/TypeScript renders the supplied mobile runtime. App UI stays in `Prototype.tsx` and `prototype.css`, HTTP types in `api.ts`. FastAPI separates authentication, sharing, extraction, review, personal reminders, dose records, notifications and report management. SQLite transactions recheck permissions and source revisions at write time.

Idempotent personal setup reuses the first owned profile and its most recent document group, or creates a private “Me / My prescriptions” context. It does not merge or delete older profiles. Uploads use that context automatically. Existing contexts remain available in account settings; a fuller dependent-management interface is deferred.

PDF text uses PyMuPDF. Images and scans use local Tesseract, including ruled-table extraction. Deterministic extraction runs first. If it finds no medication, available local Ollama/Phi can attempt source-grounded extraction with a bounded timeout. Missing OCR/model support never switches to a remote service. The original remains readable even if no care details were recognized. Handwriting and unfamiliar layouts may require manual entry.

The overview submits all fields in one transaction with a revision fingerprint. Stale reviews fail instead of overwriting another edit. Corrections retain original evidence and append before/after history. Added fields are marked manual with no fabricated source. Empty details cannot be confirmed; clarification and exclusion remain explicit. Confirmation checks transcription and is not clinical approval. The printable overview is a convenience copy, not a replacement prescription.

Personal reminders require confirmed medicine name, dose and frequency, a current review revision, explicit course dates, IANA time zone and user confirmation. Stated clock times take precedence. Every-N-hour instructions retain spacing, including overnight. Flexible daily frequencies can use editable meal/sleep routine suggestions. A plain stated number of course days must match inclusive start/end dates; the user confirms the actual start date. As-needed and unresolved instructions cannot create fixed repeating reminders. Matching medicine names with overlapping active periods are blocked across the same person's documents. This conservative exact-name check is not a complete clinical duplicate/interactions checker.

An active reminder stores an immutable instruction snapshot and source fingerprint. Field changes, added details, archive, stop and backup restore suspend it. Changing the routine only affects new suggestions; existing reminders never silently move. Old clinician requests/approvals are suspended once on upgrade; evidence/history remain exportable. Historical clinical API/storage remains for compatibility, with no clinician step in the normal UI.

## Dose records and caretaker updates

Doses use the reminder's time zone. End dates are inclusive. A nonexistent DST clock is omitted; an ambiguous clock occurs once at its first occurrence. There is no compensating dose. Taken/skipped actions are allowed after due time. Snooze moves the alert ten minutes, not the prescribed time. Undo preserves audit history. Manual as-needed records remain separate from scheduled occurrences. Neither proves ingestion or provides an adherence score.

Owners invite an existing account as viewer or recorder; acceptance is required before sharing. Viewers read; recorders can log care, update visits and undo their own entries. They cannot edit prescriptions, create reminders, delegate access or undo another actor's record. Owner-only settings select taken, skipped and not-confirmed alerts and a 5-minute to 24-hour delay. Not-confirmed means no action was recorded, not proof of a missed dose. Collection starts after consent and reminder creation, avoiding retroactive alerts from before accepted access.

The server persists an inbox event once per dose/status. Later taken/skipped/undo events supersede unread status pushes while history remains visible. Manual records also send selected status/undo updates. Revocation, archived/deleted reports and current preferences are checked before delivery. Revocation cannot recall downloaded copies or delivered messages.

Source-listed phone numbers retain actual labels and page evidence; a general phone number is never promoted to emergency. Confirmed numbers and owner-entered contacts appear in Family with tap-to-call links.

Medicine explanations use 13 exact generic-name matches and paraphrased general-use facts with NHS links and a checked date. Strength/form descriptors can be removed for matching; brands, combinations and similar spellings are not guessed. A specific indication is shown only if that medicine's own detail states it, with source/manual attribution. A diagnosis elsewhere never supplies an inferred indication. Optional local Phi selects IDs from reference facts; unsupported output is discarded. This is a small collection, not a comprehensive drug database.

## Browser notifications

Open the bell to enable notifications explicitly on that browser. In-app dose lists and caretaker inbox work without permission. Foreground checks run while visible. Background Web Push uses an app-owned service worker and persistent API worker. The local launcher sets a development VAPID subject; hosted installations use an operator-controlled contact through `AFTERCARE_PUSH_SUBJECT`.

Patient dose alerts require valid unchanged personal reminders and cover a 30-minute due window. Caretakers get only selected status updates, with a bounded 24-hour dispatch window. Completed doses do not generate patient alarms. Attempts/delivery persist, retries are bounded, and snooze permits a fresh alert. Generic push payloads contain opaque IDs and an instruction to open AfterCare, without patient, medicine, dose or document text. Push providers receive subscription/delivery metadata; files and extraction stay local.

Background delivery needs a supported secure-context browser, permission, subscription, internet and running API. OS/browser behavior may suppress or delay alerts. This is not a guaranteed alarm or emergency channel. Eligibility is rechecked at dispatch; sent messages cannot be recalled. Sign-out removes the current browser's binding. Password change/recovery and restore invalidate registrations. Rejected expired endpoints are removed. The service worker does not cache patient files or provide offline record access.

## Encryption, backup and deletion

SQLite snapshots and originals use AES-256-GCM with random nonces and filename-bound authentication. SQLite operates in memory under a process-wide lock; committed snapshots are authenticated and atomically replaced. One API process holds the installation lock. This whole-database design suits small installations, not large multi-worker services; it is not SQLCipher.

Windows local keys use the current user's DPAPI. Other local systems use a mode-0600 key file. Hosted installations require an external base64 32-byte `AFTERCARE_VAULT_KEY`, separate from the data volume. Missing keys cannot recover old ciphertext. An unlocked server/OS account can read records. Encryption does not protect runtime memory, temporary extraction files, downloads or historical filesystem blocks/snapshots. Temporary files are normally removed, not securely erased.

With the API stopped:

```powershell
.venv/Scripts/python.exe -m backend.backup create D:/private/aftercare.acb --data-dir D:/AfterCare/data
.venv/Scripts/python.exe -m backend.backup restore D:/private/aftercare.acb --data-dir D:/AfterCare/data-restored
```

Passphrases are prompted privately. Backups use scrypt-derived AES-GCM and contain consistent SQLite and originals. Restore checks authentication, paths, hashes, database integrity and source completeness before writing a new empty folder under a new vault key. Ownership/evidence/history remain; sessions, recovery codes, push registrations and queued caretaker updates are removed. Grants are revoked, historical clinician credentials disabled, and schedules suspended with consent removed. Sign in, reissue recovery codes, re-invite caretakers and reconfirm personal reminder settings. Passwords revert to backup-time values. Expanded limit: 512 MB.

Development rollback archives `data/before-v2-upgrade.acb` and `data/before-personal-reminders.acb` retain pre-upgrade records. Random passphrases are Windows-user-protected in `.upgrade-backup-pass` and `.personal-upgrade-backup-pass`. Use a portable backup with your own passphrase for another machine.

Direct report deletion works for active or archived reports. It requires owner authorization, current password and exact-name confirmation; active reports are archived as part of the confirmed operation. Original, reviews, schedules, dose states, associated alerts and care records are removed, retaining minimal deletion audit. Interrupted source operations reconcile with database state. Backups, exports, printed/downloaded copies and OS snapshots remain; this is not forensic secure erasure. Owner-only ZIP exports are unencrypted report copies, not account backups.

## Development and hosting

Use one `uvicorn backend.main:app --host 127.0.0.1 --port 8000` worker and `npm run dev -- --port 5173 --strictPort` in `frontend` for development. Offline administration/backups require stopping the API. `scripts/check.py` runs isolated behavior tests, frontend tests, TypeScript/build and protected runtime hashes. OCR fixtures are regressions, not clinical validation. Custom training and a full labeled extraction benchmark are deferred.

`Dockerfile`, `compose.yaml` and `Caddyfile` provide one Python/UI worker, Tesseract, encrypted persistent data and HTTPS proxy. Optional Ollama runs on the same host in a private container; external AI endpoints are rejected. Remote configuration fails closed without HTTPS public origin, Secure cookies and external vault key.

On an operator-owned Docker host, copy `.env.example` to private `.env`, set domain and vault key, configure DNS/ports 80/443, then `docker compose up --build -d`. For AI, enable profile `ai` and pull `phi4-mini:latest` in that local container. Keep secrets out of source control. Docker is absent here: container image, target TLS and actual push-provider delivery require target-host smoke tests. No public deployment is claimed. A Sites frontend artifact alone lacks the Python API and encrypted data service.

References: [SQLite serialization](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.serialize), [AES-GCM](https://cryptography.io/en/latest/hazmat/primitives/aead/#cryptography.hazmat.primitives.ciphers.aead.AESGCM), [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata), [Web Push](https://github.com/web-push-libs/pywebpush), [Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API).

## Manual entry and contextual timing revision

Manual medicines use the same permission-bound record and reminder workflow with `kind=manual`, `file=null`, no pages and exclusively user-attributed fields. Saving entered details is explicit confirmation; no reminder becomes active until its times/dates are confirmed. Idempotent request IDs prevent duplicate saves on retry. A shared source-name validator allows document-free records only when every field is manual and there is no source evidence; an uploaded report with a missing original still fails closed. Backup, encrypted startup, export, archive and deletion support these records without manufacturing a document.

Home's profile initial opens account settings, replacing the duplicate settings icon. The add flow offers Upload prescription or report and Add medicine manually. Manual entries remain editable in the overview and labelled in the list and print/export output.

Relative timing recognizes named breakfast, lunch, dinner, waking and bedtime anchors. Stated numeric minute/hour gaps are calculated across midnight and protected at save time. When no gap is specified, the configured anchor is suggested without inventing a medically precise delay; the user can adjust it. Repeated equivalent anchor instructions are deduplicated. Frequency conflicts, unsupported gap wording and incompatible explicit clock/interval constraints block setup rather than silently selecting one. Routine snapshots are retained for these schedules. Updating the routine never silently moves existing reminders.

Medicine explanations now retain report problem/diagnosis context with source/manual attribution and review state. A specific reason comes only from a confirmed medicine-specific Indication/Reason/Purpose or a suitable “For …” instruction, never from co-occurrence with a diagnosis. The local Phi request can include these local context excerpts together with public reference facts. The response still selects fact IDs only; generated diagnoses, prescribing reasons and unsupported medical claims are never rendered. Unknown drugs retain the original explicit context without a guessed reference match.

Validation for the practical-use revision: the complete regression run passed 122 backend tests and 6 frontend behavior tests. Additional final clock-validation cases are covered in the focused timing/manual-entry run. Production build, strict unused-code TypeScript check and all 28 runtime hashes passed. Browser verification confirms profile-initial account access, manual save without an upload, automatic continuation to routine-based reminder setup and explicit user-entered provenance. No real prescription was changed or deleted for these checks.
